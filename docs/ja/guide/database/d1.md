# D1 (SQLite) {#d1-sqlite}

[Cloudflare D1](https://developers.cloudflare.com/d1/) は、Void のデフォルトの SQLite データベースです。まず[スキーマ](../database.md#schema-definition)を用意してください。ローカルでもデプロイ時でも、データベースは Void が管理します。

## ローカルデータベース {#local-database}

開発サーバーとローカルの `void db` コマンドは、同じデータベースを共有します。`void.config.ts` の `cloudflare.d1_databases` で D1 バインディングを宣言している場合、Void はその ID を使います。ローカル開発中は `preview_database_id` が優先されます。

ローカルデータを `.void` の外に保存するには、Vite の設定で `voidPlugin({ persistTo: 'local-state' })` を設定します。データベースコマンドを実行する前に、開発サーバーを一度起動してそのディレクトリを記録させてください。Vite の設定を変更した後は、再度起動して更新します。独自の Cloudflare ランタイムを管理するフレームワークでは `.wrangler/state` を使います。

## マイグレーションとプロトタイピング {#migrations-prototyping}

`void db push` を使うと、マイグレーションファイルを作成せずにスキーマ変更をローカルに適用できます。デプロイの前に、マイグレーションを生成してコミットしてください。

```sh
void db generate
void db migrate # ローカルに適用
void deploy     # リモートに適用してデプロイ
```

ワークフロー全体については、[データベースコマンド](../../reference/cli/database.md#database)を参照してください。

## バッチ操作 {#batch-operations}

D1 は、複数のステートメントを 1 回のラウンドトリップにまとめるバッチ処理をサポートしています。

```ts
import { users, posts } from '@schema';
import { db, eq } from 'void/db';

await db.batch([
  db.delete(posts).where(eq(posts.userId, userId)),
  db.delete(users).where(eq(users.id, userId)),
]);
```

## リードレプリケーション {#read-replication}

Void は、データベースをプロビジョニングする際に [D1 のリードレプリケーション](https://developers.cloudflare.com/d1/best-practices/read-replication/)を有効にします。既存のデータベースで有効にするには、`void deploy --platform cloudflare --provision` を実行します。`void/db` の `db` を通じたクエリは、Void のリクエストごとに D1 セッションを使うため、読み取りをリクエストの近くで実行でき、そのリクエスト内の後続のクエリでは少なくとも同じデータが見えます。Void のリクエストスコープを持たないフレームワークのハンドラーでは、データベース操作のたびにプライマリから開始します。`createDb` は、渡されたバインディングに対してレプリカ対応のセッションを開始します。

リクエスト間では、レプリカに遅延が生じることがあります。認証セッションの確認はプライマリから開始されるため、失効したセッションがレプリカの遅延によって受け入れられることはありません。別の読み取りを最新のプライマリのデータから開始する必要がある場合は、`cloudflare:workers` の `env.DB.withSession('first-primary')` を使います。ほかのクエリライブラリや生の D1 呼び出しでレプリカを使うには、それぞれ独自の `withSession()` が必要です。素の D1 バインディングはプライマリから読み取ります。

## 代替のクエリレイヤー {#alternative-query-layers}

`cloudflare:workers` の `env.DB` を、別のクエリライブラリや生の D1 API と組み合わせて使えます。

### Kysely {#kysely}

```ts
import { env } from 'cloudflare:workers';
import { Kysely } from 'kysely';
import { D1Dialect } from 'kysely-d1';

const db = new Kysely<Database>({ dialect: new D1Dialect({ database: env.DB }) });
```

### 生の D1 {#raw-d1}

```ts
import { env } from 'cloudflare:workers';

const { results } = await env.DB.prepare('SELECT * FROM users WHERE id = ?').bind(userId).all();
```

どのクエリレイヤーを使っても、バインディングの推論とデプロイは引き続き Void が処理します。

::: warning ⚠️ メタフレームワークの制限
Nuxt と SvelteKit 2 は、ローカル開発中の `cloudflare:workers` のインポートをサポートしていません。`void/db` か、フレームワークのバインディングアクセス API を使ってください。SvelteKit 3 はこれらのインポートをサポートしています。
:::
